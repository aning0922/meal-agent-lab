# 项目状态

更新时间：2026-07-23

## 当前阶段

低保真原型准备。产品负责人已确认 App 功能、信息架构、核心流程、MVP 范围和推荐的开放决策方案，尚未开始业务代码实现。

## 已形成的共识

- 产品定位为家庭餐食决策与厨房库存系统，Agent 是入口而不是唯一界面。
- 首要风险是库存维护成本，而不是模型生成能力。
- 库存必须按批次和事件管理。
- 过敏、日期、权限与食品安全使用确定性校验。
- 首发应验证完整闭环，不同时建设四套独立原生客户端。
- 一级入口采用“今天、库存、采购、家庭”，Agent 作为上下文入口而非独立 Tab。
- P0 采用手动搜索、最近项、常用模板和文本录入；语音、条码及 OCR 放入 P1。
- 菜单按单道主食或 1–3 道菜的一餐组织。
- MVP 使用所有者、普通成员和无登录用餐档案三类身份。
- P0 只做应用内临期提醒，外部通知放入 P1。
- 微信小程序作为首发目标，架构保留 Android、iOS 和 HarmonyOS 扩展能力。

## 已确认的产品决策

产品层选择统一记录在 `docs/product/open-decisions.md`，已作为原型基线确认。原型阶段重点验证：

1. 首次录入能否在较低维护成本下完成。
2. 三个差异化菜单是否便于比较和选择。
3. 采购完成后的入库确认是否足够轻量。
4. 做饭完成后的库存扣减和剩菜回库是否容易理解。

跨端框架、后端运行时、登录体系、部署环境以及正式数据来源仍需在原型验证后通过技术 ADR 确认。

## 建议的下一里程碑

新开“低保真原型”任务，制作并评审首次引导、今天吃什么、采购及做饭扣减闭环；完成原型验证后再进入技术栈 ADR 和开发。
