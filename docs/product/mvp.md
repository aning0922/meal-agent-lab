# MVP 范围

- 版本：0.3
- 状态：Accepted for technical validation

## 要验证的假设

家庭愿意用很低的维护成本记录必要库存，以换取更快、更可靠的餐食决策和更少的食材浪费。

## 必须具备

- 创建家庭、邀请成员和基础角色权限。
- 成员过敏、忌口、口味、饭量和厨艺信息。
- 常用厨具与默认做饭时长。
- 食材批次录入：名称、模糊数量、日期、开封状态和储存位置。
- 常备调味品快速勾选。
- “今天谁吃、多少时间”的快速入口。
- 从审核过的结构化菜谱中建议本餐菜品数量和预选组合，并提供可增减的可选菜。
- 推荐理由、缺少食材、替代方案、难度和时间。
- 共享采购清单。
- 做完确认和半自动库存扣减。
- 临期提醒与简单反馈。

完整功能编号与行为见 [App 功能规格](app-functional-spec.md)。
所有 P0 页面状态与恢复行为见 [P0 页面状态基线](../design/p0-page-state-baseline.md)。

## P0 用户故事与验收

| 用户故事 | 最小验收结果 |
| --- | --- |
| 作为家庭所有者，我能创建家庭并记录实际用餐者 | 能创建登录成员和无登录档案；硬约束与普通偏好分开保存 |
| 作为库存维护者，我能快速录入食材 | 同食材不同购买批次不互相覆盖；未知日期可以留空且不会被系统猜测 |
| 作为做饭者，我能按今晚条件获得可执行菜单 | 选择实际参与者、时间、厨师和采购容忍度后得到建议菜品数量、预选组合、可选菜及推荐依据 |
| 作为有过敏成员的家庭，我需要安全过滤 | 自动化安全用例中硬约束零违规；替换食材后重新校验，包括调味品 |
| 作为采购者，我能共享缺货清单 | 菜单缺少项与手工项可合并，多成员修改不会产生重复或静默覆盖 |
| 作为做饭者，我能按步骤完成并更新库存 | 做完前不扣减；确认具体批次和数量后写入消耗事件，支持部分完成和剩菜回库 |
| 作为家庭成员，我需要知道哪些信息不确定 | 推荐明确显示未知库存、估算日期和关键假设；无可行结果时不编造菜谱 |
| 作为用户，我可以控制敏感数据 | 能查看主要数据用途并完成退出、移除、导出或删除路径 |

## MVP 端到端验收场景

一个新家庭能够在同一连续流程中完成：创建家庭 → 添加两名用餐者及一条硬约束 → 选择厨艺与厨具 → 录入至少五个食材批次 → 获得建议菜品数量与预选组合 → 增减可选菜并确认本餐 → 把缺少项加入共享采购清单 → 标记已买并确认入库 → 按步骤完成做饭 → 确认消耗与剩菜 → 查看更新后的库存。

该流程中任何 Agent、识别或推荐步骤都不能绕过用户确认、权限校验和食品安全规则。

## 发布阻断条件

以下任何一项失败都阻断对外内测或发布：

- 向任一本餐参与者推荐含明确过敏原或硬性禁忌的菜单；
- 漏检主料、辅料、调味品或替代品中的硬约束；
- 把规则估算显示成包装明确日期，或把购买日当作生产日；
- Agent、OCR 或模型在用户未确认时直接新增、扣减、丢弃或删除库存；
- 重试、重复点击或重复工具调用产生重复库存事件；
- 无权限成员读取或修改其他家庭或受限成员的数据；
- 工具调用失败、只完成部分操作，却向用户显示完整成功；
- 扣减产生负库存，或并发修改被静默覆盖。

安全回归至少覆盖隐藏在调味品中的过敏原、同食材不同批次、开封后期限、冷冻与解冻、模糊日期、成员约束冲突、多人并发和模型工具失败。

## P1 候选

- 语音、条码、包装日期和小票识别。
- 多菜并行时间线、多个计时器和语音陪做。
- 报餐、菜单投票、采购分派和外部提醒。
- 一周菜单、餐食历史、浪费趋势和可管理的偏好学习。
- 更完整的离线操作和跨设备恢复。

## P2 候选

- 冰箱图片批量辅助识别。
- 生鲜比价、外部下单和商业合作。
- IoT、智能冰箱和厨房设备联动。
- 菜谱社区、公开内容和复杂营养方案。

## 暂不进入 MVP

- 自动识别整个冰箱或判断食材是否新鲜安全。
- 智能冰箱与其他 IoT 设备接入。
- 医疗级营养或疾病治疗建议。
- 全量营养追踪、菜谱社区和短视频内容。
- 生鲜比价、自动下单和无人确认的 Agent 写操作。
- 同时维护四套独立原生客户端。

## 关键观测指标

- 首次录入到首份可用菜单的耗时。
- 推荐选择率和实际完成率。
- 每周库存维护时间和纠正次数。
- 临期食材经提醒后被使用或丢弃的比例。
- 第二位家庭成员加入和参与的比例。
- 连续四周仍有完成餐次的家庭比例。

指标统一定义：

- **推荐会话**：提交本餐条件且返回至少一个通过校验的候选。
- **选择餐次**：用户明确选择候选并创建本餐计划。
- **完成餐次**：用户标记做完，并完成或明确跳过消耗确认。
- **周活跃家庭**：七天内至少发生一次有效库存写入、推荐会话或完成餐次。

内测阶段建议重点观察首次价值时间、推荐选择率、已选菜单完成率、每周库存维护时间、第二位账号参与率和第四周家庭留存。数值目标在获得首轮真实样本后校准，不把估算节省量直接宣传为真实减少浪费。
