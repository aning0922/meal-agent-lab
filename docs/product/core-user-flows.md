# 核心用户流程

- 版本：0.3
- 状态：Accepted for technical validation，待目标用户验证

## 流程 1：首次获得价值

**目标：** 用户无需完整盘点冰箱，就能得到第一份可信菜单。

1. 登录并创建家庭，或通过邀请加入。
2. 添加实际会参与吃饭的成员；先填写过敏和明确禁忌，普通偏好允许跳过。
3. 选择主要做饭者的水平和现有厨具。
4. 从模板勾选常备调味品。
5. 添加 5–10 个当前最想消耗或最确定存在的食材。
6. 确认今晚参与者、可用时间和是否愿意采购。
7. 查看系统建议的菜品数量和预选组合，按需增减可选菜后确认本餐。

规则：除硬约束外均允许跳过；跳过的内容显示为未知，不自动填成否。中途退出应保存到家庭或本地草稿。

## 流程 2：快速入库

1. 从库存页点击“添加”，或从采购清单进入“已买待入库”。
2. 搜索标准食材，优先展示最近和常买项。
3. 选择模糊数量或输入精确数量。
4. 选择常温、冷藏或冷冻等位置。
5. 按信息实际来源填写购买日、生产日、标签到期日和开封状态；非必填项可以未知。
6. 核对一批或多批食材并提交。
7. 系统创建独立批次和购入事件，首页临期摘要立即更新。

异常：同名食材已经存在时默认新增批次，不覆盖旧批次；识别结果模糊时保留待确认，不进入正式库存。

## 流程 3：今天吃什么

1. 用户从今天页进入本餐设置，或直接说“今晚三个人，30 分钟，不买菜”。
2. 系统把参与者、厨师、时间、口味和采购容忍度转成可编辑条件。
3. 读取最新库存批次并执行过敏、禁忌、设备、时间和食材安全过滤。
4. 系统先建议本餐做几道菜并预选一组可执行组合，再提供目标不同的可选菜；每道菜显示时间、缺少项、库存覆盖和推荐理由。
5. 用户可增减菜品；整餐总时间、采购项和预计库存消耗随选择实时重算，也可查看详情或修改条件。
6. 确认本餐前再次检查成员约束和库存版本；整餐缺少项可一键加入共享购物清单。

异常：没有可行菜单时展示具体阻塞原因，并给出“允许补购、增加时间、换厨师、补充库存信息”等动作，不能自由编造一个不满足条件的菜单。

## 流程 4：家庭共同采购

1. 已选菜单把缺少项加入清单，用户也可手动添加。
2. 系统合并同类项，但保留原始来源和数量拆分。
3. 家庭成员在购物现场勾选，其他成员看到最新状态和操作者。
4. 已买项目进入“待入库”，用户可以继续购物，不强迫立即补全日期。
5. 回家后批量确认数量、日期和储存位置，正式生成库存批次。

异常：两人同时勾选同一项时只产生一次状态变更；已被他人修改的数量应基于最新值合并或提示冲突。

## 流程 5：做饭与扣减库存

1. 打开已选菜单，开始前确认人数、缺少项、准备工作和关键安全提示。
2. 按步骤做饭；退出后可以恢复进度。
3. 完成或中止时在“完成与库存确认”页选择“全部完成、部分完成、没有做”。
4. 同一页面按选择渐进展示预计使用的具体库存批次和数量；“没有做”保持零消耗。
5. 用户调整或排除后最终确认，系统写入消耗事件。
6. 剩余熟食或原料可作为新批次回库。
7. 记录口味、难度和时间反馈，只影响软偏好与后续排序。

异常：做饭期间库存被其他成员修改时，根据最新批次重新计算，不允许出现负库存；无法确定的消耗标记为待盘点。

## 流程 6：处理临期和不确定食材

1. 首页展示需优先处理的批次，区分标签日期、开封后要求和规则估算。
2. 用户可选择“用它找菜单、更新信息、已经用完、丢弃、稍后处理”。
3. “找菜单”预填必须使用的食材，但仍执行所有硬约束和安全过滤。
4. 丢弃时记录可选原因，用完或丢弃后更新库存。

规则：过期或安全状态未知的高风险食材不提供“尽量利用”入口；产品不能根据外观或气味保证可食用。

## 流程 7：邀请与家庭协作

1. 所有者生成有时效的邀请。
2. 新用户登录并确认加入哪个家庭。
3. 可将已有用餐档案与新登录用户关联，避免出现两个同名成员。
4. 新成员按权限访问库存、菜单和购物清单。
5. 退出或移除成员时说明个人信息和家庭共享记录如何处理。

异常：邀请过期、已使用、家庭已满或当前用户已属于该家庭时给出可恢复的明确结果。

## 核心状态模型

### 一餐计划

```text
草稿 → 已生成建议 → 已确认组合 → 待采购/可做 → 做饭中 → 已完成
                    └────────────────────→ 已取消
```

### 购物项目

```text
待购买 → 已买待入库 → 已入库
   └──────────────→ 已取消
```

### 识别或 Agent 写操作

```text
解析中 → 待确认 → 已提交
   └────→ 部分成功/失败 → 修改后重试
```

## 全流程状态要求

所有流程都必须保留首次空状态、加载、未知、失败、无权限、部分成功、并发冲突、安全阻断、重复提交与中途恢复。登录恢复、库存搜索与历史、邀请隐私和 Agent 二级页已经纳入可点击 P0 原型；具体状态语义见 [P0 页面状态基线](../design/p0-page-state-baseline.md)。

流程跨页时遵守以下规则：

1. 返回或取消不把草稿变成正式写入。
2. 已买、已入库、已完成做饭和已确认扣减分别记录，不由页面跳转隐式推进。
3. 重试复用同一幂等请求；重复提交返回原结果。
4. Agent 只带入上下文或生成待确认变更，不改变状态机权限。
