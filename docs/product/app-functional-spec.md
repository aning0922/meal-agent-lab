# App 功能规格

- 版本：0.3
- 状态：Accepted for technical validation
- 更新时间：2026-07-23

## 1. 目的

本文把产品方向拆成可以设计、开发和验收的 App 功能。当前只定义用户可感知行为和业务边界，不绑定具体前端框架、后端语言或模型供应商。

## 2. 优先级

- `P0`：构成“记录食材 → 推荐菜单 → 采购 → 做饭 → 扣减库存”闭环，MVP 必须完成。
- `P1`：闭环验证后提高效率、留存和跨平台体验。
- `P2`：规模化、商业化或生态扩展能力。

优先级表示产品顺序，不代表可以跳过安全、隐私、空状态或错误处理。

## 3. 用户与权限

MVP 先保持三类身份：

| 身份 | 说明 | 主要权限 |
| --- | --- | --- |
| 家庭所有者 | 创建家庭的登录用户 | 管理成员、家庭设置和所有共享数据；转移或解散家庭 |
| 家庭成员 | 通过邀请加入的登录用户 | 查看共享信息；按权限维护库存、菜单和购物清单 |
| 用餐档案 | 儿童、老人或未注册成员 | 被选择为用餐者并保存约束，不直接登录和操作 |

P0 不做复杂自定义角色。敏感限制可以只对本人和所有者可见，但必须以不可绕过的形式参与推荐校验。

## 4. 一级信息架构

底部导航建议保持四项：

1. **今天**：临期提醒、今晚参与者、菜单推荐、继续做饭。
2. **库存**：现有食材、批次、位置、状态和快速操作。
3. **采购**：共享购物清单及买后入库。
4. **我的**：个人资料为入口，包含家庭成员、偏好、厨艺、厨具和隐私设置。

Agent 不单独占用一级导航。在今天页、菜单详情、库存和采购页提供带当前上下文的入口，完整对话作为二级页面打开。

## 6. 全局交互状态

每个 P0 页面都必须定义以下状态，而不是只设计成功页面：

- **首次空状态**：说明为什么需要数据，并提供一个最短动作。
- **加载状态**：避免重复提交，长任务显示当前阶段或可取消入口。
- **无数据或信息未知**：未知不等于没有；展示来源、置信度和补充入口。
- **网络、服务失败或离线**：说明哪些内容没有保存，提供同一幂等请求重试且保持用户输入；数据陈旧时显示最后同步时间。
- **无权限**：说明当前身份缺少什么权限，不暴露敏感数据。
- **部分成功**：批量录入或工具调用中逐项显示成功、待确认和失败项。
- **多人并发冲突**：库存或购物清单已被他人修改时，基于最新状态重新计算，不简单覆盖。
- **安全阻断**：说明硬约束、日期或食品安全原因，只提供修改条件、补信息或移除风险项。
- **重复提交**：返回第一次成功结果，不创建重复库存、采购或消耗事件。
- **返回、取消和中途恢复**：说明已保存与未写入范围；页面重载不得自动完成或扣减。

统一状态语义与页面专属处理见 [P0 页面状态基线](../design/p0-page-state-baseline.md)。

## 7. 产品级业务规则

1. 任何推荐都以“本餐实际参与者”为硬约束集合。
2. 已过期或安全状态未知的高风险食材不参与正常推荐。
3. 未录入的食材是未知，不直接判定为家里没有。
4. 写库存、删除、丢弃和修改硬约束必须可追溯，必要时可通过纠正事件恢复。
5. Agent、OCR 和图片识别只生成候选变更，不能绕过确认与服务端校验。
6. 选择菜单和开始做饭前都要用最新库存与成员约束重新校验。
7. 购物项的“已买”和库存的“已入库”是两个状态。
8. 临时请求不能自动升级为永久偏好，行为推断不能升级为硬约束。

## 8. 产品事件定义

为避免不同端和后端对指标理解不一致，P0 至少统一以下事件：

| 事件 | 定义 |
| --- | --- |
| `household_created` | 服务端成功创建家庭，重复请求只计算一次 |
| `first_inventory_confirmed` | 家庭首次确认至少一个正式库存批次 |
| `recommendation_generated` | 提交本餐条件并返回至少一个通过校验的候选菜单 |
| `recommendation_selected` | 用户明确选择一个候选并创建本餐计划 |
| `shopping_item_purchased` | 项目进入已买待入库，不等同于库存增加 |
| `meal_completed` | 用户标记做完，并完成或明确跳过本次消耗确认 |
| `inventory_deduction_confirmed` | 本餐实际消耗事件成功写入 |
| `expiry_item_actioned` | 用户对临期或待确认批次执行了使用、纠正、移动或丢弃动作 |

通用分析平台只记录流程与性能信息，不发送具体过敏、健康信息、完整食材明细或家庭成员名称。
