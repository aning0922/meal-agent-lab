# Meal Agent 低保真原型独立评审

- 评审日期：2026-07-23
- 评审对象：低保真原型 v0.2
- 修订结果：产品基线 v0.3
- 结论：Accepted for technical validation（按现有已确认产品决策）

## 1. 评审方法

评审先独立阅读产品、流程、信息架构与食品安全基线，再实际运行原型，分别在 390 × 844 窄屏和桌面评审视图走查首次引导、推荐、采购、入库、做饭、库存扣减和剩菜回库。

除成功路径外，逐页检查首次空状态、加载、未知、失败、无权限、部分成功、并发冲突、安全阻断、重复提交与中途恢复。未把上一版原型已有交互视为默认正确。

## 2. 已解决问题

### 发布阻断

1. **页面状态缺失。** 增加全局状态模拟器和 [P0 页面状态基线](p0-page-state-baseline.md)，覆盖 11 类状态及页面专属处理。
2. **采购状态未迁移。** 食材现在按“待购买 → 已买待入库 → 已入库”迁移；确认入库后不再停留在待入库，重复提交不再创建批次。
3. **非食材被错误入库。** 厨房纸等非库存物品买完即完成，不创建 `InventoryLot`。
4. **菜单不满足本餐条件仍可确认。** 超时、不买菜却有缺货、缺少一餐主体、厨艺未知和缺少必需设备均显示原因并禁用确认。
5. **开始做饭可绕过缺货。** 开始前校验失败时禁用“开始做饭”，只提供回到条件或采购的恢复动作。
6. **做饭步骤用量错误。** 当前步骤只显示所属菜品的实际用量。
7. **临期与高风险未知食材缺少对应交互。** 增加库存与临期页；标签日期、用户录入和未知状态分开展示，高风险未知生鸡肉不提供利用入口。
8. **Agent 上下文入口不完整。** 今天、库存、菜单、采购和做饭页均可打开带当前对象的 Agent；结果回到结构化页面，写操作只生成待确认单。

### 高优先级

1. **首次引导伪造默认值。** 新家庭不再预选成员硬约束、厨艺、厨具、调味品和食材；跳过保持未知。
2. **关键按钮无交互。** 添加用餐档案、搜索添加食材、手动添加采购项和暂停恢复已可操作。
3. **“已买”和“已入库”不够可信。** 购物项显示当前状态；买后入库回执明确批次数量和幂等结果。
4. **日期来源标错。** “已买时间”标为系统记录，不再冒充用户输入的购买日；购买日、生产日和包装日期可以保持未知。
5. **餐后默认写入意图过强。** 完成状态默认“全部完成”，剩菜回库默认不选；部分完成可先按菜排除，再调整具体批次。
6. **做饭无法恢复。** 暂停会保存当前步骤，今天页提供继续入口；暂停不会完成餐次或扣减库存。

### 中优先级

1. 可选菜增加“更丰盛、 更省时、更合口味”三个统一取舍方向，仍采用已确认的“预选组合 + 可选菜增减”。
2. 人数、硬约束数量、设备数量、菜单份量和校验文案改为使用当前状态，不再硬编码。
3. 补充库存和家庭一级页面，使信息架构与原型入口一致。
4. 补齐原型构建所需的站点辅助文件，恢复本地构建与测试。

## 3. 仍需产品负责人决定

### RV-001 三个完整菜单还是组合增减

- 当前已确认决策：PD-014 使用“建议菜品数量 + 预选组合 + 可选菜增减”，不做三个完整菜单三选一。
- 本次任务表述：要求检查“三个差异化菜单的比较与选择”。
- 推荐：维持 PD-014，在目标用户测试中比较三个明确的加菜取舍方向；只有用户持续无法理解组合时，才重新打开 PD-014。
- 影响：若改成三个完整菜单，会改变推荐返回结构、比较页面和选择事件，必须在技术接口冻结前确认。

### RV-002 是否合并“完成状态”和“库存扣减”

- 当前基线：先选全部、部分或没做，再核对具体批次。
- 推荐：技术验证先保持两步，但记录从“做完了”到确认扣减的完成时间；若多数用户认为重复或无法在 45 秒内完成，再评估合并为同页渐进披露。
- 影响：会改变完成餐次、跳过扣减和剩菜回库的交互顺序。

### RV-003 第四个一级导航名称

- 当前基线：继续使用“家庭”，包含“我的资料”。
- 推荐：按 PD-013 与“我的”做文案可用性对比，不影响首轮技术验证。

## 4. 可进入技术验证的结论

在继续沿用 PD-014 的前提下，v0.3 已满足进入技术验证的产品基线要求：

- MVP 成功路径能够从创建家庭走到库存扣减与剩菜回库。
- 采购、库存和餐次状态不再互相矛盾。
- 所有核心页面状态有统一契约和页面专属定义。
- 过敏、日期来源、库存未知、食品安全、权限、并发和幂等均有可验证的阻断或恢复行为。
- Agent 保持为业务页面的上下文能力，不成为独立一级导航或绕过结构化确认。

技术验证只验证实现可行性、契约和关键风险，不代表跨端框架、后端运行时、身份体系、部署环境或正式数据来源已经决定。
