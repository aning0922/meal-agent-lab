## 一级页面职责

### 今天

目标是让用户最少操作完成一顿饭，而不是展示大量统计信息。

从上到下建议为：当前家庭与同步状态、需要优先处理的食材、本餐参与者和时间、主要“今天吃什么”按钮、已选择菜单或最近可恢复任务、单行 Agent 输入。

### 库存

顶部优先呈现“需处理、全部、常备”三个视角。列表默认显示聚合食材，临期或状态不同的批次可以展开。主操作是快速添加，次级操作是搜索、筛选和批量盘点。

### 采购

以购物现场单手使用为目标。当前未完成项目优先，已买项目折叠。每项显示名称、建议数量、来源菜单和最后操作者；勾选后可进入买后入库确认。

### 家庭

集中管理低频但重要的家庭上下文。成员约束、厨艺和设备优先于通用偏好设置。敏感信息只显示完成校验所需的最少内容。

## 全屏任务页

以下流程不使用底部导航打断：首次引导、建议组合与可选菜、做饭模式、完成扣减和敏感信息确认。退出时需要保存草稿或明确提示未保存内容。

## Agent 入口

Agent 是上下文能力而非独立目的：

- 今天页：提出完整本餐需求。
- 库存页：查询、添加或纠正库存。
- 菜单页：替换、解释或降低难度。
- 采购页：查询为什么要买、合并或修改项目。
- 做饭页：询问当前步骤，但不得跳过安全提示。

对话结果应尽可能转成菜单卡片、库存确认单或购物项目，而不是只停留在聊天文本中。
