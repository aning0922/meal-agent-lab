# P0 页面状态基线

- 版本：0.1
- 状态：Accepted for technical validation
- 更新时间：2026-07-23

## 1. 目的

本文定义 Meal Agent P0 页面在成功路径之外必须具备的状态和恢复行为。技术验证可以使用模拟数据，但不能只验证“正常返回”；任何端、Agent 或服务实现都必须遵守同一状态语义。

低保真原型的“当前页面状态模拟”可以在每个原型页面切换以下状态。原型未单独绘制的 P0 辅助页也必须按本文实现。

## 2. 全局状态契约

| 状态 | 必须展示 | 主操作 | 禁止行为 |
| --- | --- | --- | --- |
| 首次空状态 | 数据用途、最短起步动作 | 完成一个最短动作 | 用演示数据冒充用户事实 |
| 加载状态 | 正在读取或写入的对象、可取消条件 | 等待或取消 | 保持提交按钮可重复点击 |
| 无数据或信息未知 | 未知字段、来源和补充入口 | 补充或保持未知 | 把未知当成没有、正常或安全 |
| 网络或服务失败 | 未保存范围、保留的输入、重试结果 | 使用同一幂等请求重试 | 清空输入或显示完整成功 |
| 无权限 | 当前身份缺少的权限、可返回页面 | 返回或请求所有者处理 | 暴露受限成员或其他家庭数据 |
| 部分成功 | 每项成功、待确认和失败结果 | 只重试失败项 | 把批量部分成功汇总成全部成功 |
| 多人并发冲突 | 最新操作者、版本变化和重算结果 | 接受最新结果或重新编辑 | 静默覆盖、产生负库存 |
| 安全阻断 | 触发的硬约束、日期或安全原因 | 修改条件、补信息或移除风险项 | 提供“仍然继续”或 Agent 绕过入口 |
| 重复提交 | 第一次成功结果和操作时间 | 查看原结果 | 再创建库存、采购或消耗事件 |
| 返回、取消和中途恢复 | 已保存范围、未写入范围、恢复位置 | 继续、放弃或安全返回 | 页面重载自动完成、扣减或提交 |
| 正常成功 | 写入对象、操作者和可纠正入口 | 进入下一步 | 用成功文案掩盖待确认项 |

离线或数据陈旧归入“网络或服务失败”和“并发冲突”处理：读取页面可展示最后同步时间；安全、权限、库存和共享清单写操作必须重新联网校验。

## 3. 当前原型页面专属状态

下表只写页面特有处理；未重复列出的加载、失败、重复提交和权限行为沿用全局契约。

| 页面 | 空状态 / 信息未知 | 部分成功 / 并发冲突 | 安全阻断 | 返回 / 恢复 |
| --- | --- | --- | --- | --- |
| O-01 首次欢迎 | 没有家庭时只展示创建或加入 | 邀请失效、已使用和家庭已满分别说明 | 无 | 离开前不产生家庭记录 |
| O-02 成员与硬约束 | 先只有所有者；硬约束未确认时不能继续 | 多档案保存逐项反馈；同名档案要求关联或更名 | 硬约束必须二次确认 | 保留家庭名、成员草稿和未确认限制 |
| O-03 厨艺与厨具 | 跳过后明确为未知，不保留默认勾选 | 设备更新冲突显示最新家庭设置 | 缺少必需设备的菜不能成为可执行方案 | 保留当前选择；允许明确清空 |
| O-04 常备调味品 | 未选中为未知，不是没有 | 模板部分保存时逐项列出 | 调味品仍参加过敏原校验 | 保留模板选择 |
| O-05 首批食材 | 0 项时提供最近项和搜索；日期、位置可未知 | 批量提交逐项显示成功、待确认、失败 | 高风险安全状态未知不进入推荐 | 保存待确认批次草稿；取消不写正式库存 |
| H-01 今天 | 没有库存也能设置本餐，但说明推荐覆盖受限 | 同步陈旧时显示最后同步时间 | 临期卡不能鼓励使用高风险未知食材 | 恢复当前菜单、做饭进度或未完成采购 |
| I-01 库存与临期 | 区分空库存、搜索无结果和批次信息未知 | 批次被他人修改后刷新历史与快捷操作 | 已过期或高风险未知批次没有“用它找菜单” | 快捷操作先形成确认单，可取消 |
| R-01 本餐条件 | 0 位参与者不能推荐；厨艺或设备未知明确显示 | Agent 解析部分字段时保留原句并逐项确认 | 所有参与者硬约束不可取消 | 返回保留本餐临时条件，不升级为永久偏好 |
| R-02 建议组合与可选菜 | 无可行结果时给出具体放宽动作 | 库存变化后重算时间、采购和覆盖率 | 超时、缺设备、不买菜却有缺货等组合不能确认 | 保留已选菜和其余已确认条件 |
| R-03 本餐组合详情 | 现有、缺少和未知食材分栏 | 确认前版本变化回到重算结果 | 最新硬约束或库存校验失败时禁用确认 | 返回继续增减菜；取消不创建餐计划 |
| S-01 共享采购 | 空清单提供手动添加和返回菜单 | 同项多人勾选幂等；合并冲突显示来源拆分 | 无权限成员不能改共享清单 | 离开不要求立即入库；保留已买状态 |
| S-02 已买待入库 | 没有已买食材时返回采购；非库存物品不进入此页 | 逐项创建批次；失败项单独重试 | 未知日期不补造；来源不明的高风险食材待确认 | 取消保留“已买待入库”，不增加库存 |
| F-01 家庭设置 | 没有其他成员时提供邀请或用餐档案 | 同名档案、邀请状态和设备更新分别处理 | 普通成员不能修改他人敏感限制 | 未保存敏感信息必须明确提示 |
| C-01 开始前检查 | 缺少信息列出具体项 | 库存变化后重新校验 | 缺货未入库、设备缺失或硬约束失败时没有开始入口 | 返回菜单不改变库存 |
| C-02 做饭模式 | 当前步骤必须有菜品、用量和安全点 | 做饭中库存变化只影响餐后重算，不静默改步骤 | Agent 不得跳过安全提示 | 暂停保存步骤；重载不完成、不扣减 |
| C-03 完成状态 | 默认“全部完成”，可改部分或没做 | 无 | “没做”必须保持零消耗 | 返回做饭保留步骤；选择没做可直接结束 |
| C-04 库存扣减与回库 | 数量不准可标记待盘点；剩菜默认不勾选 | 按最新批次重算；无法确定的部分待盘点 | 不允许负库存；剩菜需制作时间、数量和位置 | 返回保留调整；取消不写消耗和剩菜批次 |
| C-05 完成回执 | 没做时明确零消耗 | 只展示真正写入的事件和失败项 | 无 | 可从操作历史纠正，不删除原事件 |

## 4. 未单独绘制的 P0 辅助页

以下页面进入技术验证时必须实现状态契约，但不要求在本轮低保真主路径中增加独立视觉页面：

- 登录与恢复：邀请过期、账号无家庭、新设备恢复、无权限和退出。
- 库存搜索、筛选、批次详情与操作历史：搜索无结果、来源未知、事件部分写入和纠正。
- 邀请、隐私、导出与删除：所有者权限、敏感信息最少披露、异步任务失败与恢复。
- Agent 二级页：工具加载、无结果、部分成功、失败、权限、安全阻断、写操作确认和同一待确认操作纠错。

这些辅助页在技术方案、接口契约和测试用例中不得被视为 P1。

## 5. 技术验证验收

技术验证至少证明：

1. 重试和重复点击不产生重复事件。
2. 部分成功不会被聚合成完整成功。
3. 库存和采购并发变更不会被静默覆盖。
4. 安全、权限和硬约束阻断在 Agent 与结构化页面一致。
5. 草稿恢复不会自动完成餐次或扣减库存。
6. 日期、数量和库存未知在端到端传递中保持未知及其来源。
