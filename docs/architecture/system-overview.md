# 系统概览

## 状态

候选架构，等待首发平台与技术栈 ADR 确认。

## 逻辑边界

```text
跨平台客户端 / 运营端
          │
     统一 API 契约
          │
账号与家庭 ─ 库存与批次 ─ 菜谱与菜单 ─ 购物清单 ─ 通知
          │               │
      关系数据库      规则与约束引擎
                          │
                    Agent 编排层
                     │         │
                  模型服务   OCR/识别服务
```

## 初始架构原则

- 客户端共享领域契约，通过平台适配器处理登录、分享、相机、通知和本地存储差异。
- 服务端从模块化单体开始，保证领域边界清晰但不提前拆分部署。
- 关系数据库是家庭、库存、权限和菜单事实的权威来源。
- 多端写操作具有幂等标识；库存使用事件流水和服务端版本处理并发。
- Agent 通过受限工具读取或修改业务状态，不能直接连接数据库。
- 常规筛选、日期计算和硬约束不依赖模型。
- 图片、小票和导入任务通过异步任务处理，并保留原始来源与审核状态。

## 平台策略

计划按照“共享业务层 + 平台薄适配层”组织。首发平台先完成闭环验证，其余平台复用 API、领域规则、设计令牌和尽可能多的页面实现。

需要通过技术验证覆盖：登录、邀请分享、相机和扫码、本地存储、离线提交、推送或订阅消息、深链、真机性能及商店构建。
